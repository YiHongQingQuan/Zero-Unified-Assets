# Zero-Unified-Assets

> 按赛项归档的技术资产仓库

## 关于 Zero-Unified-Assets

一个按「赛项 / 课程」分目录归档的仓库。每个子目录是一个独立项目，各自带一份 README，
说明它做了什么、依赖什么、怎么跑起来、有哪些已知问题。

仓库本身**不是**某个项目的工程目录，而是多届、多赛项的集合，所以没有统一的构建方式 ——
先进到具体项目目录，再看它的 README。

## 目录结构

```
Zero-Unified-Assets/
├── 00_快速入门、工具、课程资料/      入门指引、自研工具、课程资料
├── 01_CCCC/                          计算机设计大赛
├── 02_GPLT/                          团体程序设计天梯赛
├── 03_MathematicalModeling/          数学建模
├── 04_Astar/                         百度之星
├── LICENSE                           MIT，适用于全仓库
├── .gitignore                        通用忽略规则（Unity / Python / 密钥）
└── .gitattributes                    换行符与二进制文件的统一约定
```

**每个一级目录都有自己的 `README.md` 作为入口**，具体内容在那一层展开，这份总 README 只画到一级。

目录命名约定：`NN_大类/YYYY_项目名/`。`NN` 用于控制排序，年份前缀用于区分届次。
`00_` 留给跨赛项的通用内容（入门指引、工具、课程资料），`01_` 之后按赛事编号。

空的预留目录里放了 `.gitkeep`，否则 git 不会保存空文件夹。

## 怎么用

1. **第一次来，从 [快速开始](00_快速入门、工具、课程资料/01_Getting-Started/README.md) 看起** —— 环境装好再往下走；
2. 按上表进入感兴趣的目录，读那一层的 `README.md`，它再往下指到具体项目；
3. 具体项目的 README 里有「快速开始」和「脚本索引」，写清楚每个文件的职责与要绑定的方法；
4. 手上已有旧版场景、想升级脚本的，读项目目录下的 `MIGRATION.md`。

## 新增一个项目

1. 建目录 `NN_大类/YYYY_项目名/`（`00_` 分段内的子目录直接按类型命名）；
2. 里面至少放一份 `README.md`：做了什么 / 环境要求 / 如何运行 / 已知问题；
3. 在**上级目录**的 README 索引表里加一行，否则别人找不到；
4. 只提交源码与文档，构建产物交给 `.gitignore`；
5. 密钥、账号、个人信息一律不进仓库（见下一节）。

### 关于虚拟环境与构建产物

**Python 的 `.venv/` 千万不要提交**：通常有几千个文件、几十 MB，提交后仓库会瞬间膨胀，
而且**无法通过删除文件瘦身**——历史里会永久保留。

根 `.gitignore` 已统一排除 `.venv/`、`__pycache__/`、`*.pyc`、`.pytest_cache/`；
新工具该怎么组织目录，见 [02_Tools/README.md](00_快速入门、工具、课程资料/02_Tools/README.md)。

## 密钥与隐私

仓库是公开的，只放代码。API Key 统一放在项目内的 `Assets/StreamingAssets/api-config.json`，
由 `.gitignore` 排除，仓库里只保留 `api-config.example.json` 模板。

提交前自查：

```bash
git grep -n -i -E 'apiKey|client_secret|sk-[a-zA-Z0-9]{16,}|"secret"' -- . ':!*example*'
```

结果为空再提交。误传过的密钥请到服务商后台**吊销并重新生成**，删文件是救不回 git 历史的。
